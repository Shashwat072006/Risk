ENGINEERING EXECUTION
Technical Obstacles & How We Solved Them
Real-world engineering hurdles overcome during platform design and implementation
1. Extreme Class Imbalance (0.17%)
Challenge: In 284k transactions, only 492 were fraud. Naive models predict 100% legitimate transactions.

Solution: Engineered scale_pos_weight optimization, PR-AUC loss targeting, and stratified split validation to maximize recall without flooding false alarms.
2. Sub-50ms Latency Budget
Challenge: Payment networks mandate <100ms authorization. Running 13 rules + ML + SHAP risked latency timeouts.

Solution: Vectorized rules in NumPy, compiled XGBoost to C++ tree runtime, and parallelized execution to reach 42ms median latency.
3. SHAP Explainability Bottleneck
Challenge: KernelSHAP takes 500ms+ per sample, making inline real-time explainability impossible.

Solution: Switched to TreeExplainer with pre-computed background summaries, yielding exact local Shapley values in ~8ms.
4. Dynamic State Synchronization
Challenge: Updating threshold weights without server restarts or causing state drift on live clients.

Solution: Built a thread-safe singleton RiskConfig manager in FastAPI with atomic REST updates broadcasting to frontend subscribers.
